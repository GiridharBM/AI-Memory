# Release Notes — v0.10.0 (Phase 4: Document Knowledge Graph)

**Released:** 2026-08-08
**Phase:** Phase 4 — per-task engineering reviews `docs/PHASE_4_P4-101..105_ENGINEERING_REVIEW.md` (all APPROVED) and the phase final approval `docs/PHASE_4_FINAL_APPROVAL.md`

---

## What's New

- **Entity & relationship domain models** — `app/domain/entity_relationship.py`: validated, deterministically serializable `Entity`, `Relationship`, `EntityMetadata`, `RelationshipMetadata`, and `SourceReference`, reusing the existing `EntityType`/`ImportanceLevel`/`EdgeType` vocabulary and `DocumentChunk` provenance conventions. Deterministic JSON (`to_dict`/`to_json`/`from_dict`/`from_json`), `extra="forbid"`, JSON-safe metadata validation, offset pairing and self-loop rejection. (P4-101)
- **Entity extraction** — `app/infrastructure/document_intelligence/entities/extractor.py`: deterministic, offline, regex-based `EntityExtractor` (technology-version and person-honorific patterns), structure-block-aware scanning with global offset stitching, code-block exclusion, first-rule-wins overlap resolution, and deterministic `Entity.make_id` normalization. (P4-102)
- **Relationship detection** — `app/infrastructure/document_intelligence/relationships/detector.py`: deterministic `RelationshipDetector` emitting `related_to` edges from co-occurrence within a shared section/document; canonical lexicographic direction, evidence-merge dedup, deterministic ordering; empty/missing-entity safe. (P4-103)
- **Document graph construction** — `app/infrastructure/document_intelligence/graph/builder.py`: `DocumentGraphBuilder` maps extracted entities and detected relationships onto the existing in-memory `KnowledgeGraph` abstraction (no graph database, no persistence). Deterministic ordering, dedup by node/edge key, missing-endpoint edges skipped with a logged warning. `find_relationships` conjunctive filter and `graph_to_dict` (mirrors `KnowledgeGraph.save`) round out the milestone. (P4-104)
- **Graph queries** — `app/infrastructure/document_intelligence/graph/query.py`: `get_entity`, `related_entities` (undirected BFS with a visited set and `max_depth`/`limit` caps), `nodes_by_source`, `query_graph` (roadmap §5.2 Python-API shape), and `graph_from_dict` — the inverse of `graph_to_dict` that loads the pipeline's `metadata.extra["knowledge_graph"]` artifact into a queryable graph without a disk round-trip. All queries are deterministic, cycle-safe, and return `None`/`[]` (never raise) for unknown ids and empty graphs. (P4-105)
- **Config + wiring** — `EntitySettings`/`RelationshipSettings`/`GraphSettings` (`app/core/config.py`), `config/default.yaml` toggles, and three failure-contained `IngestionWorkflow` enrichment stages attaching `metadata.extra["entities"]`, `metadata.extra["relationships"]`, and `metadata.extra["knowledge_graph"]`.

---

## Behavior Changes

- `IngestionWorkflow` now attaches three additive enrichment keys (`entities`, `relationships`, `knowledge_graph`) to document `metadata.extra` for text-bearing sources. Each is individually disableable; a disabled toggle omits its key entirely (R-4), producing M2.2-identical documents.
- Extraction is deterministic and offline — no external service; relationship detection and graph construction likewise run entirely in-process.
