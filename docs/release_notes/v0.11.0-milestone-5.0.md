# Release Notes — v0.11.0 (Phase 5: Hybrid Retrieval)

**Released:** 2026-08-09
**Phase:** Phase 5 — per-task engineering reviews `docs/PHASE_5_P5-101..105_ENGINEERING_REVIEW.md` (all APPROVED) and the phase final approval `docs/PHASE_5_FINAL_APPROVAL.md`

---

## What's New

- **Deterministic BM25 sparse retrieval** — `app/infrastructure/bm25.py`: custom Okapi-BM25 index (`k1=1.5`, `b=0.75`) with tokenized term-frequency and IDF scoring, pure stdlib. Deterministic `(-score, doc_index)` tie-break gives byte-stable result ordering. No `rank_bm25` dependency. (P5-101, P5-102)
- **Reciprocal Rank Fusion** — `app/infrastructure/search.py` `_rrf_fuse` merges dense and BM25 candidate sets with `k=60` (roadmap 4.2), replacing the previous `0.7*semantic + 0.3*keyword` weighted sum. Fused results can include documents from either source even when the other scores them low. (P5-102)
- **Scoring verification** — `tests/unit/test_scoring.py` locks the roadmap 4.1 success criterion: searching "Python async" ranks the keyword-exact document above a semantically-similar-but-unrelated "threading" document; also covers BM25-over-baseline ordering, RRF fusion correctness, and metadata preservation. (P5-103)
- **`SearchService` facade** — `app/infrastructure/search.py:200` exposes the MEDD §7.6 contract `search(query, *, top_k=5, filter=None, min_score=0.0) -> list[SearchHit]`; `SearchService.create_default(settings)` reads the same persisted `manifest_root/vector_store.json` the ingest pipeline writes and embeds via the configured model. `SearchHit` carries `text`, `source`, `score`, `entry_id`, `parent_section`, `source_type`, `chunk_index`, `start_char`, `end_char`, and `metadata`. (P5-104)
- **`pam search` CLI** — `app/cli/entry.py:362`: `pam search <query> [--top-k N] [--filter JSON] [--source-type T] [--min-score F]` renders a Rich table with score, source, and snippet. Validates blank queries (exit 1), `--top-k >= 1` (exit 2), and `--filter` JSON (exit 1); service failures exit 1 with a message. (P5-104)
- **Retrieval performance** — precomputed entry norms in `VectorStore` (O(1) dense legs), a mutation counter (`store.version`) that version-keys the BM25 index cache so it rebuilds exactly when the corpus changes, and deterministic `(-score, entry.id)` ordering. `VectorEntry` gains additive `start_char`/`end_char` fields (round-tripped through JSON persistence). (P5-105)
- **Metadata filtering** — exact-match filters against entry fields then metadata keys (entry field wins) via `VectorStore.search(filters=...)` and `SearchService.search(filter=...)`; `pam search --filter`/`--source-type` merge. Structured `$in` syntax deferred as roadmap 4.5. (P5-105)
- **Resilient fallback** — embedder failure or a `None`/empty embedding degrades to lexical-only (BM25); a BM25 build or search failure degrades to dense-only with the cache reset (no poisoned cache, self-healing on the next query). (P5-104, P5-105)

## Behavior Changes

- `HybridSearch` fusion changed from weighted sum (`0.7` semantic + `0.3` keyword) to **reciprocal rank fusion (k=60)** over dense + BM25 candidates.
- `VectorStore.search` results are now deterministically ordered (`(-score, entry.id)`) and scoring uses precomputed norms with identical semantics to the previous `_cosine_similarity` (dimension mismatch / zero vector → `0.0`).
- Search is now reachable from the command line (`pam search`) — previously `SemanticSearch`/`HybridSearch` were library classes only.
- No Phase 1–4 module behavior modified beyond the retrieval stack; all changes are additive or confined to `search.py`/`vector_store.py`/`bm25.py`/`app/domain/vector_store.py`/`app/cli/entry.py` (search command).

## Rollback

- **Config:** none added in Phase 5 — retrieval has no new toggle; `pam search` simply queries the existing store.
- **Code:** Phase 5 is additive; deleting `bm25.py`, the RRF/facade additions in `search.py`, the `VectorStore` optimization in `vector_store.py`, and the `search` CLI command restores the pre-Phase-5 codebase. `VectorStore.search` falls back to brute-force `_cosine_similarity` semantics if norms/versioning are removed (same scores, same results).
- **Data:** `VectorEntry` gains two optional fields (`start_char`/`end_char`); `_load` tolerates their absence (`None`), so pre-Phase-5 persisted stores load unchanged.
- **Dependency:** none (no new dependencies introduced).
