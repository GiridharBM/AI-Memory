**Released:** 2026-08-08

## What's New

- **Native heading hierarchy metadata** — `SemanticChunker` (`app/infrastructure/semantic_chunking.py`) emits `metadata.extra["heading"]`, `heading_path` (ancestry, e.g. `"M3 » §1 » ¶"`), and `heading_level` on every chunk; heading-parent ID assignment is resolved natively in-chunker (P3-201 O-1 — user-selected over the Milestone 2.3 `DocumentStructure` consumption seam, recorded as a deviation in the review). This resolves MEDD gap G14 (flat chunk list → parent tracking). (P3-201)
- **List-aware chunking** — `_ListBlock` tokens split at whole top-level list items (consecutive numbered/bulleted/checklist lines grouped per item); a list item is never split mid-item across chunks; non-list paragraph text is unaffected. (P3-202)
- **Code-aware chunking** — fenced code blocks become single atomic chunks with `language` metadata (`markdown` fences supported; `"generic"` fallback); inline code is masked during sentence splitting so backticks cannot fragment a code span. (P3-203)
- **Structured-content preservation** — Markdown/HTML tables, blockquotes, callouts, and definition lists are emitted byte-for-byte with `kind` metadata (`html_table`/`table`/`blockquote`/`callout`/`definition`); block-boundary overlap is forced on so content integrity is never traded for dedup. (P3-204)
- **Adaptive `ChunkingPolicy`** — frozen policy dataclass with `heading_size_step` (per-heading-depth budget bump; `0` = flat), `min_chunk_chars` (coalescing floor for short items), `snap_overlap`/`snap_max_back` (sentence/paragraph/list-boundary overlap snap-back), and `heading_overlap_boundary` (headings as hard boundaries). Flat defaults reproduce the M3.1 algorithm bit-for-bit (P3-204 regression gate). (P3-205)
- **Config + plumbing** — `ChunkingSettings` (`app/core/config.py:364`) exposes the five policy fields; `config/default.yaml:171-177` lists all keys with `"P3-205:"` comments; `create_default` (`app/pipelines/ingest_workflow.py:247-254`) builds the policy; both the CLI (`app/cli/entry.py:372`) and the queue worker (`app/queue/worker.py:84`) reach it. (P3-205)

---

## Behavior Changes

- `SemanticChunker` is now a block tokenizer: top-level blocks are parsed first (`_split_blocks` — structured kinds + heading-led sections, paragraphs, lists), then decomposed with heading-aware recursion. Under flat defaults the M3.1 recursive sentence-splitting path is preserved (P3-204 regression gate).
- `ChunkingPolicy` replaces scattered constructor kwargs; the chunker is constructed with a `policy` field.
- Chunks now carry heading context (`heading`, `heading_path`, `heading_level`) — downstream retrieval can use parent/ancestor context that was previously unavailable.
- Overlap is policy-driven: sentence/paragraph/list snap and heading hard-boundary behavior are opt-in knobs, all defaulting to the M3.1 byte-compatible behavior.

## Known Issues

- **Per-task atomic commits not yet made (roadmap §8):** milestone work uncommitted in the worktree; commit per-task atomic commits before release (same status as M2.1–M3.1).
- **Pre-existing test debt (O-3):** `tests/integration/smoke_test.py::test_live_ollama_analysis_and_note_generation` requires a running Ollama server and is a pre-existing environmental flake (this run: generated note missing one section — LLM output variance, unrelated to chunking). `test_ocr_pipeline.py` skips without a Tesseract binary. Neither touches chunking code.
- **Character-based sizing remains (G13):** chunk sizing is still character-based; token-aware `tokenizer`/`max_chunk_tokens` are reserved for Milestone 3.3 (MEDD naming decision C-1).
- **Heading hierarchy is heading-driven, not section-driven:** section-level semantics from the structure subsystem (`metadata.extra["structure"]`) are not consumed (P3-201 O-1 deviation); revisit if structure-based parenting is later required.
