# Release Notes — v0.7.0 (Milestone 2.6: Code & Notebook Intelligence)

**Released:** 2026-08-04
**Milestone:** Phase 2, Milestone 2.6 — see `docs/PHASE_2_IMPLEMENTATION_SPECIFICATION.md` (frozen §4.6) and `docs/PHASE_2_MILESTONE_2_6_IMPLEMENTATION_ROADMAP.md`

## What's New

- **Code & notebook domain models** — `CodeStructure`, `CodeImport`, `CodeFunction`, `CodeClass`, `NotebookCell`, `NotebookStructure` pydantic models (additive, `extra="forbid"`, offsets validated `end >= start`) in `app/domain/document_intelligence.py`. (P2-601)
- **Language registry** — `app/infrastructure/document_intelligence/code/languages.py` `language_from_filename(filename)` maps every suffix in `extensions.CODE_EXTENSIONS` to a human-readable language name (`.py` → `"python"`, `.js` → `"javascript"`, …); unknown extensions → `"generic"`; case-insensitive. Pure dict, no dependencies. (P2-602)
- **Python AST parser** — `app/infrastructure/document_intelligence/code/parser.py` `_AstCodeParser` (stdlib `ast`): extracts imports, functions (incl. `async def`), classes with nested methods, docstrings, and accurate line/char offsets (Python 3.12 `end_lineno`/`end_col_offset`). (P2-603)
- **Heuristic fallback parser** — `_HeuristicCodeParser`: line-based regex parsing for non-Python code files and syntax-invalid Python; **never raises** (returns empty `CodeStructure` on unparseable input). `parse_code(text, filename)` dispatches: Python → AST, everything else → heuristic. (P2-604)
- **Notebook parser + ingestor upgrade** — `app/infrastructure/document_intelligence/code/notebook.py` `NotebookParser`/`parse_notebook`: ordered typed cells (`markdown`/`code`/`raw`) with `execution_count`, outputs capped at `max_cell_outputs` (beyond-cap entries → `"[truncated]"`), kernel + language from notebook metadata; never raises on malformed input. `NotebookIngestor` now attaches `metadata.extra["notebook_structure"]` while preserving the existing flattened fenced text (backward compatible). (P2-605)
- **Pipeline enrichment wiring** — `intelligence.code.*` config (`CodeSettings` in `app/core/config.py`, `code:` block in `config/default.yaml`) + `_enrich_code()` hook in `app/pipelines/ingest_workflow.py` at the shared P2-305 call site (beside `_enrich_structure`/`_enrich_tables`/`_enrich_images`). For `kind == "code"`: `parse_code(document.text, document.filename)` → `metadata.extra["code_structure"]`. For `kind == "notebook"`: passes through the `notebook_structure` already attached by the ingestor. Gated by `intelligence.code.enabled` **and** `kind in {"code", "notebook"}`. `CodeProcessor`/`NotebookProcessor` remain passthrough (M2.4 TableProcessor pattern). (P2-606)

## Behavior Changes

- Code files (`.py`, `.js`, … 20+ extensions) and Jupyter notebooks (`.ipynb`) now carry structured parse output under `metadata.extra["code_structure"]` / `metadata.extra["notebook_structure"]` when `intelligence.code.enabled: true`. Existing flattened text output is unchanged.
- `max_code_chars: 100000` caps parsed source length (Python `str` length) — oversized code is truncated at parse time with a logged warning. `max_cell_outputs: 10` caps per-cell notebook outputs during parsing. Both are plumbed from config through `DocumentIngestionService` → `parse_code` / `NotebookIngestor` → `parse_notebook`.
- `languages: "default"` selects the built-in `code/languages.py` suffix→language map (over the `CODE_EXTENSIONS` suffix set from `app/core/extensions.py`); other values are not supported in M2.6 (extensibility deferred, contract-only C-5). `include_docstrings` is contract-only this milestone (C-5 precedent): declared, read by no code.
- Rollback contract: `intelligence.code.enabled: false` ⇒ no `code_structure` / `notebook_structure` keys — documents identical to pre-M2.6 (Phase-1) passthrough (notebook structure is popped from `extra` in the disabled path). (R-4)
