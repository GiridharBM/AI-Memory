## What's New

- **Sentence tokenizer protocol + factory** — `app/infrastructure/sentence_tokenizer.py` `SentenceTokenizer` Protocol (`split(text) -> list[str]`, D5 contiguous-span contract: text partitions into spans `s₁…sₙ` with whitespace-only separators consumed at sentence boundaries) + engine registry (`register_sentence_tokenizer`) + `get_sentence_tokenizer(engine="auto")` factory. Unknown/unregistered engine → clear `SentenceTokenizerSelectionError`; empty/whitespace-only text → `[]`; engine selection resolved once per chunker instance (D8). (P3-101)
- **Heuristic stdlib engine** — `_HeuristicSentenceTokenizer` (registered unconditionally — the guaranteed `"auto"` fallback): abbreviation-aware (Dr., Mr., U.S.A., a.m., e.g., etc.), ellipses, decimal numbers, quoted sentences, `!?` terminators, and CJK `。！？` with empty boundary separators (D7). Zero new dependencies. (P3-102)
- **Optional NLTK `punkt_tab` engine** — `_NltkSentenceTokenizer` (import-guarded): pretrained `PunktTokenizer("english")` backed by `nltk.download("punkt_tab")` (one-time setup for the optional `intelligence` extra; nltk ships no bundled data; runtime stays offline). Registered only when nltk and its data are present; `"auto"` prefers it. `nltk>=3.9` added to the `intelligence` optional extra (D4/C-2 — no new *required* runtime dependency). (P3-103)
- **`SemanticChunker` integration** — `sentence_tokenizer: str = "auto"` dataclass field (`app/infrastructure/semantic_chunking.py`); `_split_by_sentences` delegates to the resolved engine; `_SENTENCE_END` regex removed; heading/paragraph/overlap logic and the `start_char`/`end_char` offsets math unchanged (D5/D5a). (P3-104)
- **Config + plumbing** — `ChunkingSettings` (`app/core/config.py:364`, `sentence_tokenizer: Literal["auto","nltk","heuristic"] = "auto"`) + top-level `chunking:` block (`config/default.yaml:171`) + the single construction site `create_default` → `SemanticChunker(sentence_tokenizer=...)` (`app/pipelines/ingest_workflow.py:247`). Both the CLI (`app/cli/entry.py:372`) and the queue worker (`app/queue/worker.py:84`) reach it. (P3-105)
- **Regression + fixture suite** — `TestSemanticChunkingAllEnginePaths(TestSemanticChunking)` re-runs the full existing 15-test chunking suite under `heuristic`/`nltk`/`auto` (R-2; nltk path import-guarded; existing tests byte-identical); committed fixtures `tests/fixtures/chunking/{abbreviations.md, cjk.md}` with D5 span-reconstruction; new integration suite `tests/integration/test_chunking_pipeline.py`. (P3-106)

## Behavior Changes

- Sentence splitting is now engine-based instead of the `(?<=[.!?])\s+(?=[A-Z\d])` regex. With `sentence_tokenizer: "auto"` (default), the NLTK `punkt_tab` engine is used when the `intelligence` extra is installed; otherwise the stdlib heuristic handles the same cases (abbreviations, decimals, ellipses, CJK) with one logged warning — ingestion never breaks (C-3 DoD).
- `overlap_chars` is now live: `SemanticChunker._apply_overlap` prepends the previous chunk's trailing `overlap_chars` characters (default 200) to each subsequent chunk. This is the previously-dead Phase 1 field.
- No `"regex"` legacy engine value is retained (Phase 2 R-4); the heuristic is a superset of the old regex and the R-2 regression gate proves all existing chunking tests pass unchanged under every engine path.

## Requirements

- **New optional dependency:** `nltk>=3.9` added to the `intelligence` extra (one-time `nltk.download("punkt_tab")` setup step for the nltk engine; runtime offline).
- **No new required runtime dependency.** The heuristic engine is stdlib-only and is the guaranteed `"auto"` fallback.

## Known Issues

- **Per-task atomic commits not yet made (roadmap §8):** milestone work uncommitted; commit per-task atomic commits before release (same status as M2.1–M2.6).
- **Pre-existing test debt (O-3):** `tests/integration/smoke_test.py::test_live_ollama_analysis_and_note_generation` requires a running Ollama server and is a pre-existing environmental flake — untouched by M3.1. Integration run: 31 passed / 1 skipped (Tesseract) / 1 failed (this live-Ollama smoke test).
- **Heuristic engine is abbreviation-list-bound:** uncommon abbreviations followed by a new sentence may be merged; the nltk engine is the upgrade path (roadmap O-1).
- **Character-based sizing remains (G13):** chunk sizing is still `max_chunk_chars` (2000 chars), not token-aware; `tokenizer`/`max_chunk_tokens` are reserved for Milestone 3.3.
- **`tiktoken` undeclared (C-3):** importable in the environment but absent from `pyproject.toml`; M3.3 must declare it formally.
