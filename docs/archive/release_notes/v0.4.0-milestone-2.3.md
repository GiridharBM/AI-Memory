# Release Notes — v0.4.0 (Milestone 2.3: Document Structure Analysis)

**Released:** 2026-08-02
**Milestone:** Phase 2, Milestone 2.3 — see `docs/PHASE_2_MILESTONE_2_3_ENGINEERING_SPECIFICATION.md` (v1.1, frozen)

---

## What's New

- **Document structure analysis subsystem** — `app/infrastructure/document_intelligence/structure/detector.py` with a pure-stdlib `StructureAnalyzer` that detects the hierarchical structure of a document (ATX headings, sections, paragraphs, lists, code fences, blockquotes, tables) and represents it as typed `DocumentStructure` / `DocumentSection` / `DocumentBlock` models with stable IDs and exact character offsets.
- **Heading hierarchy detector** — nested `#` levels build a correct parent/child tree; a document-global fence state ensures `#` inside triple-backtick code fences is never mis-split as a heading; heading levels above 6 normalize to 6.
- **Block detector** — paragraph / list / code fence / blockquote / Markdown table blocks with accurate `start_char`/`end_char` offsets into the analyzed text.
- **Enrichment into the surviving document** — for `markdown`/`text` kinds with `intelligence.structure.enabled: true`, the serialized structure is stored at `document.metadata.extra["structure"]` on the enriched `SourceDocument` (the same channel `parent_id` uses). `ProcessedDocument` is unchanged.
- **Performance + cap guard** — text above 5 MB is skipped with a single warning; `MAX_SECTIONS` (10 000) truncates with a warning, never raises; single O(n) linear scan within the ≤ 1 s / 1 MB ceiling.
- **Shared enrichment call site** — the `_run_routed_processor` hook is the attachment point Milestones 2.4 (tables), 2.5 (images), and 2.6 (code/notebook) reuse.
- **Zero new dependencies** — pure `re` + `pydantic`; no wheel verification needed.

## Behavior Changes

- Markdown and plain-text documents now carry a `metadata.extra["structure"]` dict when the flag is enabled (default `true`); the note output and chunking behavior are unchanged (the chunker keeps its internal heading-split copy — byte-identical regression).
- `intelligence.structure.enabled: false` restores Milestone 2.2-identical documents — no `"structure"` key is written and all consumers treat a missing key as "no structure".
- `enrich_analysis_input` is declared but **not read** by any code this milestone (contract-only field, addendum 3 / R-7).

## Requirements

- None. Pure stdlib parsing; `ollama`/pydantic already present. No new runtime or optional dependencies.

## Known Issues

- Regex-based, best-effort parsing: `#` inside HTML/attributes and exotic list nesting are not fully handled (only fenced-code disambiguation is guaranteed).
- Structure analysis currently applies to `markdown`/`text` kinds only; PDF/OCR-prose kinds are excluded until a consumer exists.
- The structure is an input contract only — no consumer yet (Phase 3 hierarchical chunking reads `metadata.extra["structure"]` → `DocumentStructure.model_validate` → `DocumentSection.id` → chunk `parent_id`).

Set `intelligence.structure.enabled: false` — no `metadata.extra["structure"]` key is written and documents are identical to the Milestone 2.2 state (additive schema only, no migration).
