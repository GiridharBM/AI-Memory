# Release Notes — v0.2.0 (Milestone 2.1: OCR Engine)

**Released:** 2026-08-01
**Milestone:** Phase 2, Milestone 2.1 — see `docs/PHASE_2_IMPLEMENTATION_SPECIFICATION.md`

---

## What's New

- **OCR engine subsystem** — OCR extracted from processor-inline helpers into a decoupled `DocumentOcrService` registry (`app/infrastructure/document_intelligence/ocr/`) with a `OcrEngine` protocol, so new OCR backends plug in without touching routing.
- **Vision primary, Tesseract fallback** — `engine="auto"` uses the local vision model first and falls back to CPU-only Tesseract when the vision model is unavailable. Explicit `engine="vision"|"tesseract"` selection also supported.
- **Per-page confidence** — OCR results carry per-page and mean confidence; low/empty-confidence pages are flagged. Confidence surfaces in the note frontmatter (`ocr_confidence`) and reference line.
- **Configurable scanned-PDF OCR** — page cap (`page_limit`, default 5, `0` = all), render zoom, and a `max_pages` hard cap replace the previous hardcoded first-5-pages limit. A failed page degrades instead of aborting the pass.
- **Shared image preprocessing** (`imaging/preprocess.py`) — deskew → denoise → CLAHE, shared with future milestones; off by default, enabled via `intelligence.ocr.preprocess`.
- **Configurable OCR/vision/handwriting prompts** — `intelligence.prompts.*` with a `{language}` slot; defaults byte-identical to prior behavior.
- **`pam doctor` OCR diagnostics** — reports OCR enablement, engine/page limit, vision-model presence, Tesseract binary availability, and package presence.
- **Robustness** — PyMuPDF absence now raises a clear `ImportError` with install instructions instead of silently returning empty text.

## Behavior Changes

- `enabled: false` in the OCR block returns an empty registry → processors passthrough (previous behavior preserved as a config option, not a code branch).
- Backward-compatible `vision_client=` kwarg on the three processors still works.
- Vision-required documents (`image`, `scanned_pdf`, `handwritten`) still fail loudly rather than being sent to a text-only model.

## Requirements

- **Optional:** [Tesseract OCR](https://github.com/tesseract-ocr/tesseract) binary + `uv pip install pytesseract pillow` for the offline fallback and preprocessing. Not required for the default vision-based path.

## Known Issues

- No layout preservation (tables/columns lose reading order).
- Handwriting is routed by source type, not ML-detected.
- Live Ollama smoke tests remain flaky when the local model is cold-starting.

## Verification

- 506 tests pass / 2 deselected (508 collected); coverage 87.02%.
- `ruff` and `mypy` — no new findings vs. baseline.
- See `docs/PHASE_2_MILESTONE_2_1_COMPLETION_REPORT.md` and `docs/DOCUMENTATION_UPDATE_REPORT.md`.

## Rollback

OCR defaults reproduce prior behavior (page cap 5, vision primary, byte-identical prompts). Set `intelligence.ocr.enabled: false` to disable the subsystem entirely.
